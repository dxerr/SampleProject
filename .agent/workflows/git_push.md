// turbo-all

이 워크플로우는 현재까지 진행된 프로젝트의 변경 사항들을 확정(commit)하고 원격 저장소로 업로드(push)하기 위해 실행됩니다.

## 실행 규칙

1. 모든 Git 명령은 시스템 터미널의 `run_in_terminal` 도구로 실행합니다.
2. 실패(merge conflict, push 거부, 인증 실패 포함)가 발생하면 무단 해결을 시도하지 않고 즉시 중단 후 주인님께 보고합니다.
3. 커밋 메시지는 한국어로 작성합니다. 변경 의도가 불명확하면 커밋 전에 주인님께 확인을 구합니다.

## 절차

1. 변경 사항 존재 여부를 확인합니다.
	- `git status --porcelain`
	- 변경이 없으면 "커밋/푸시할 변경 없음"으로 보고하고 종료합니다.

2. 변경 사항이 있으면 pull을 먼저 시도합니다.
	- `git pull --rebase --autostash`
	- 실패 시 즉시 중단하고 6번 규칙(중단 후 보고)을 적용합니다.

3. 커밋/푸시 단위를 분리합니다.
	- 최소 단위는 각 Plugin입니다.
	- 서로 다른 상위 경로(예: `Plugins/ExNetwork`, `Plugins/ExRunnerPlay`, `Source`, `Config`)의 변경은 하나의 커밋으로 섞지 않습니다.

4. 각 단위별로 스테이징/커밋/푸시를 반복합니다.
	- 스테이징: `git add .`를 기본으로 사용하되, 단위 분리가 필요하면 `git reset` 후 대상 경로만 다시 스테이징합니다.
	- 커밋: `git commit -m "[한글 커밋 메시지]"`
	- 푸시: `git push`

5. 모든 단위의 푸시가 성공하면 주인님께 정중한 한국어로 완료 보고를 합니다.

6. 중간 실패 시 처리 원칙:
	- 자체 해결 금지
	- 즉시 작업 중단
	- 실패 지점/오류 요약/대기 상태를 주인님께 보고
