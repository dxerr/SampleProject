# 멀티플레이어 바닥 청크 동기화 및 물리 틈새 끼임 버그 해결

## 증상
1. **정상화되었던 청크 겹침 스폰 현상 재발**: `SetNetAddressable()` 적용 후 클라이언트에서 바닥 청크가 겹쳐서 2개씩 스폰됨.
2. **클라이언트 움직임 롤백 및 버벅임**: 클라이언트 캐릭터가 청크를 지날 때마다 주기적으로 이전 위치로 강제 이동(롤백)됨.
3. **디버그 박스(서버 위치)의 급격한 공간 점프 착시**: 디버그 라인 확인 시 서버 위치가 첫 번째 청크에서 두 번째 청크(커브)로 2칸 점프한 것처럼 보이는 현상.
4. **클라이언트가 특정 청크 경계에서 멈추는 현상 (물리 끼임)**: 서버는 다음 청크로 정상 진입하지만, 클라이언트 폰은 청크 경계(예: 직선 끝 -> 커브 진입 지점)에 투명 벽이 있는 것처럼 막혀서 전진하지 못함.

## 원인 분석
1. **리플리케이션(Replication)과 로컬 스폰의 충돌**:
   - `ExRunner` 맵은 시드 기반으로 클라이언트/서버가 각자 바닥을 생성함.
   - `SetNetAddressable()` 추가 후 서버의 청크가 클라이언트로 복제되며, 로컬 청크 1개 + 서버 청크 1개 = 2개가 겹침.

2. **디버그 박스 2개 청크 점프(착시)의 진실**:
   - 디버그 박스가 청크의 '중심 좌표'에 너무 거대하게 그려지고 있었음. 두 번째 커브 청크의 중심이 너무 멀어서 시각적으로 2칸 점프한 것처럼 착각하게 만듦.

3. **클라이언트 물리 끼임 (투명 벽) 현상**:
   - 스플라인 메시는 수학적으로 완벽히 맞닿아 있더라도 부동소수점 오차로 인해 아주 미세한 틈새(Seam)나 턱(Lip)이 발생함. 
   - 틱 속도가 다른 클라이언트에서 물리 캡슐의 Sweep 검사가 우연히 이 미세한 턱에 걸리며 전진 속도를 0으로 만들어버림. 서버는 틱 타이밍이 달라 우연히 이 턱을 부드럽게 넘어간 것임.
   - 엎친 데 덮친 격으로 `UpdateLanePosition`에서 매 틱마다 `TargetPawn->SetActorLocation(..., false)`를 호출하여 폰을 강제로 텔레포트시키고 있었음. Mover 물리 시뮬레이션 중에 강제 텔레포트를 쓰면 턱에 끼인 상태에서 억지로 밀어넣는 꼴이 되어 물리 엔진(Chaos)이 강한 반발력으로 폰을 뒤로 밀어냄. 이로 인해 경계선을 넘지 못하고 영원히 고립됨.

## 해결 방법
1. **청크 리플리케이트 비활성화 강제 (`ExFloorChunk.cpp`)**:
   - 생성자와 `BeginPlay()`에서 `bReplicates = false` 강제 적용. 겹침 스폰 원천 차단.
2. **직관적인 디버그 시각화 개선 (`ExRunnerPositionSyncComponent.cpp`)**:
   - 디버그 박스 크기를 대폭 줄이고 화면에 **(Range: 1500 ~ 3070)** 등 거리 구간 텍스트를 출력해 직관성 강화.
3. **매 틱 텔레포트(SetActorLocation) 제거 (`ExRunnerMovementComponent.cpp`)**:
   - `UpdateLanePosition`에서 위험한 `SetActorLocation`을 제거. Mover의 Pure Pursuit 조향이 이미 오프셋을 반영해 자연스럽게 레인 중앙으로 유도하므로 강제 텔레포트 불필요.
4. **미세 틈새 방지용 물리 오버랩 추가 (`ExFloorChunk.cpp`)**:
   - `ApplyCurve()`에서 직선 청크는 길이를 `10.0f` 연장하고, 커브 청크는 각도를 `0.5도` 연장시켜 바닥들이 기와장처럼 살짝 겹치도록(Overlap) 수정. 물리 엔진이 턱에 걸리지 않고 매끄럽게 슬라이딩하도록 근본적인 충돌 문제 해결.

## 테스트 방법
1. C++ 코드를 `Ctrl+Alt+F11` (Live Coding) 로 컴파일.
2. 에디터에서 멀티플레이어로 플레이하여 클라이언트 창 확인.
3. 클라이언트가 직선에서 커브 청크로 넘어갈 때 더 이상 경계선에 걸려 버벅거리거나 멈추지 않고, 서버와 함께 완벽히 부드럽게 넘어가는지 확인.
