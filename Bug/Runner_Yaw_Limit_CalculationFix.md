# 러너 플레이 Yaw 입력 제한 버그 수정 (뒤로 돌아가는 현상)

## 현상파악
- 조이스틱 스와이프 시 지정된 최대 각도(예: 10도)를 넘어 계속 회전하거나 특정 상황에서 모델이 뒤로 도는 현상이 발생했습니다.
- 원인은 `RequestLookAction`의 기존 제한(Clamp) 로직에 결함이 있어, 조이스틱 입력값 자체를 단순히 누적해버리거나 실제 회전 델타값을 정확히 제어하지 못했기 때문입니다. 즉, 캐릭터가 지정 각도 바깥으로 넘어가려 할 때, 초과된 양이 제대로 상쇄되지 않고 엔진의 입력 시스템(`AddControllerYawInput`)에 그대로 전달되는 식의 의도치 않은 작동이 있었습니다.

## 조치 내용
`UExRunnerInputComponent::RequestLookAction` 함수의 연산 로직을 직관적이고 견고한 Clamp 방식으로 전면 수정했습니다.

1. **목표 Offset 계산**: `현재 누적 각도 + (이번 프레임 조이스틱 입력 * 민감도)`로 이번 프레임의 최종 목표 각도(`DesiredYawOffset`)를 계산합니다.
2. **절대 한계 제한**: 언리얼의 `FMath::Clamp()` 함수를 사용하여 목표 각도를 `-MaxAngle`과 `+MaxAngle` 사이로 강제 고정합니다 (`ClampedYawOffset`).
3. **실질 델타 추출**: 고정된 최종 각도에서 기존 누적 각도를 빼서 이번 프레임에 *실제로 엔진 컨트롤러에 하달해야만 하는* 진짜 증분(`ActualDeltaYaw`)만을 알아냅니다.
4. **누적값 동기화 및 전송**: 현재 누적 각도를 고정된 값으로 업데이트하고, 실질 증분이 존재할 때만 브로드캐스트하여 BP에서 `AddControllerYawInput`으로 전달되게 합니다.

이제 아무리 크게 스와이프하거나 오래 누르고 있어도 정확하게 한계 각도에 걸리게 되며, 반대 방향 스와이프 시에도 정확하게 정해진 각도 범위 내에서만 반응합니다.
