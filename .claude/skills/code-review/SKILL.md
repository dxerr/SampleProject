## Phase 1: 대상 파일 로드

대상 파일들을 전체 읽기. CLAUDE.md에서 프로젝트 코딩 표준 확인.

---

## Phase 2: ExFrameWork 표준 준수 검사

CLAUDE.md 기준으로 평가:

**네이밍 (1.2)**:
- [ ] Ex 접두사 사용 (UEx..., AEx..., FEx..., EEx..., IEx...)
- [ ] Boolean 변수에 `b` 접두사 (bIsReady 등)
- [ ] PascalCase 적용

**UE5 베스트 프랙티스 (1.7)**:
- [ ] Raw Pointer(`*`) 대신 `TObjectPtr<T>` 사용
- [ ] `LogTemp` 대신 프로젝트 전용 로그 카테고리
- [ ] 필수 포인터에 `check()` / `ensure()` 어설트 적용
- [ ] 생성자 내 `NewObject<>` 미사용 (대신 `CreateDefaultSubobject<>`)

**헤더 파일 구조 (1.9)**:
- [ ] `.generated.h` 가 마지막 `#include` 에 위치

**생성자 규칙 (1.10)**:
- [ ] 생성자에서 `NewObject<>` 미호출
- [ ] `CreateDefaultSubobject<>` 또는 `Init...` 계열 함수 사용

**데이터 드리븐 설계 (1.3)**:
- [ ] 하드코딩된 매직 넘버 없음
- [ ] 조정 가능한 값은 `UPROPERTY` 노출

**모듈 분리 (4.1)**:
- [ ] Core 모듈이 Feature 모듈을 참조하지 않음
- [ ] 의존성 방향 올바름 (Feature → Core)

---

## Phase 3: 아키텍처 및 SOLID

**아키텍처:**
- [ ] 올바른 의존성 방향
- [ ] 순환 의존성 없음
- [ ] 적절한 레이어 분리 (UI가 게임 상태를 소유하지 않음)
- [ ] 크로스 시스템 통신에 이벤트/델리게이트 사용

**SOLID:**
- [ ] 단일 책임: 각 클래스는 변경 이유가 하나
- [ ] 개방/폐쇄: 수정 없이 확장 가능
- [ ] 리스코프 치환: 서브타입이 기본 타입 대체 가능
- [ ] 인터페이스 분리: 비대한 인터페이스 없음
- [ ] 의존성 역전: 구체적 구현이 아닌 추상화에 의존

---

## Phase 4: UE5 특화 검사

- [ ] 프레임 독립성 (델타 타임 사용)
- [ ] 핫 패스에서 할당 없음 (업데이트 루프)
- [ ] 적절한 널/빈 상태 처리
- [ ] 멀티플레이어: `HasAuthority()` 확인
- [ ] 리소스 정리 (누수 없음)
- [ ] 불필요한 Tick 대신 이벤트 드리븐 패턴
