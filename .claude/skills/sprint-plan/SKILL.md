## Phase 1: 컨텍스트 수집

1. `Md/Plans/` 폴더에서 현재 진행 중인 플랜 파일 읽기
2. `git log --oneline -10` 으로 최근 커밋 히스토리 확인
3. git status로 현재 작업 중인 변경사항 파악

## Phase 2: 스프린트 계획 생성

인수(`new`, `update`, `status`)에 따라 적절한 출력 생성:

**`new` 또는 인수 없음:**

```markdown
# 스프린트 [N] -- [시작일] ~ [종료일]

## 스프린트 목표
[이 스프린트가 마일스톤에서 달성하는 것을 한 문장으로]

## 용량
- 총 일수: [X]
- 버퍼 (20%): [Y일 예비]
- 가용: [Z일]

## 작업 목록

### Must Have (핵심 경로)
| ID | 작업 | 담당 | 예상 일수 | 의존성 | 완료 기준 |
|----|------|------|-----------|--------|-----------|

### Should Have
| ID | 작업 | 담당 | 예상 일수 | 의존성 | 완료 기준 |
|----|------|------|-----------|--------|-----------|

### Nice to Have
| ID | 작업 | 담당 | 예상 일수 | 의존성 | 완료 기준 |
|----|------|------|-----------|--------|-----------|

## 이전 스프린트 이월
| 작업 | 이유 | 새 예상 |
|------|------|---------|

## 리스크
| 리스크 | 확률 | 영향 | 완화 방법 |
|--------|------|------|-----------|

## 이 스프린트 완료 정의
- [ ] 모든 Must Have 작업 완료
- [ ] 모든 작업이 완료 기준 충족
- [ ] 코드 리뷰 및 머지 완료
- [ ] 디자인 문서 이탈 사항 업데이트
```

**`status`:**

```markdown
# 스프린트 [N] 상태 -- [날짜]

## 진행률: [X/Y 작업 완료] ([Z%])

### 완료됨
| 작업 | 완료일 | 비고 |

### 진행 중
| 작업 | 진행률 | 블로커 |

### 미시작
| 작업 | 위험 여부 |

### 차단됨
| 작업 | 블로커 | 예상 해결일 |
```

## Phase 3: 사용자 승인 후 저장

계획을 보여준 후 승인을 요청한다.
승인 시 `Md/Plans/Sprint_[N]_[YYYYMMDD].md` 에 저장.

**주의**: CLAUDE.md 3.1 규칙에 따라 반드시 사용자 승인 후에만 파일을 작성한다.
