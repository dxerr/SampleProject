## Phase 1: 인수 파싱

모드 결정:
- 인수 없음 또는 설명 → **설명 모드**: 제공된 설명으로 버그 리포트 생성
- `analyze [path]` → **분석 모드**: 파일을 읽고 잠재적 버그 식별

인수가 없으면 버그 설명을 요청한다.

---

## Phase 2A: 설명 모드

1. 설명 파싱: 무엇이 깨졌는지, 언제, 재현 방법, 예상 동작
2. 관련 파일 검색 (Grep/Glob)
3. 버그 리포트 작성:

```markdown
# 버그 리포트

## 요약
**제목**: [간결하고 설명적인 제목]
**ID**: BUG-[NNNN]
**심각도**: [S1-크리티컬 / S2-주요 / S3-경미 / S4-사소]
**우선순위**: [P1-즉시 / P2-다음 스프린트 / P3-백로그]
**상태**: Open
**보고일**: [날짜]

## 분류
- **카테고리**: [게임플레이 / UI / 오디오 / 비주얼 / 성능 / 크래시 / 네트워크]
- **시스템**: [영향받는 게임 시스템]
- **빈도**: [항상 / 자주(>50%) / 가끔(10-50%) / 드물게(<10%)]
- **리그레션**: [예/아니오/불명 — 이전에 작동했었나?]

## 환경
- **브랜치**: [현재 브랜치]
- **플랫폼**: [OS, 하드웨어]
- **씬/레벨**: [게임 내 위치]
- **게임 상태**: [관련 상태]

## 재현 단계
**전제조건**: [시작 전 필요한 상태]

1. [정확한 단계 1]
2. [정확한 단계 2]
3. [정확한 단계 3]

**예상 결과**: [무슨 일이 일어나야 하는가]
**실제 결과**: [실제로 무슨 일이 일어났는가]

## 기술 컨텍스트
- **영향 가능성 있는 파일**: [코드베이스 검색 기반 파일 목록]
- **관련 시스템**: [관련된 다른 시스템]
- **가능한 근본 원인**: [설명으로 식별 가능한 경우]

## 비고
[추가 컨텍스트 또는 관찰 사항]
```

---

## Phase 2B: 분석 모드

1. 인수로 지정된 파일 읽기
2. 잠재적 버그 식별: 널 참조, 오프바이원, 경쟁 조건, 처리되지 않은 엣지 케이스, 리소스 누수
3. 각 잠재적 버그에 대해 위 템플릿으로 리포트 생성

---

## Phase 3: 저장

완성된 버그 리포트를 사용자에게 제시한다.

승인 요청: "`Md/Bug/BUG-[NNNN]_[제목요약].md` 에 저장할까요?"

승인 시 파일 저장. **CLAUDE.md 3.1 규칙에 따라 반드시 승인 후에만 저장.**

---

## Phase 4: 다음 단계

파일 저장 후 제안:
- S1 또는 S2인 경우: 즉시 수정 작업 시작 권장
- 분석 모드인 경우: 발견된 잠재적 버그 중 우선순위 확인 권장
