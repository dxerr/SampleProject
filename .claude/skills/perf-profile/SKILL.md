## Phase 1: 범위 결정

인수 읽기:
- 시스템 이름 → 해당 시스템 집중 프로파일링
- `full` → 전체 시스템 포괄 프로파일링
- 인수 없음 → 현재 작업 중인 변경사항 기준으로 범위 결정

---

## Phase 2: 성능 버짓 로드

기존 성능 목표 확인:
- 목표 FPS (60fps = 16.67ms 프레임 버짓)
- 메모리 버짓 (총량 및 시스템별)
- 로드 타임 목표
- 드로우 콜 버짓
- 네트워크 대역폭 한도 (멀티플레이어)

---

## Phase 3: 코드베이스 분석

**CPU 프로파일링 대상:**
- `Tick()` 함수 — 모두 목록화 및 비용 추정
- 대용량 컬렉션에 대한 중첩 루프
- 핫 패스의 문자열 연산
- 프레임별 코드의 할당 패턴
- 게임 엔티티에 대한 비최적화 검색/정렬
- 매 프레임 비용 큰 물리 쿼리 (레이캐스트, 오버랩)

**메모리 프로파일링 대상:**
- 대용량 데이터 구조 및 성장 패턴
- 텍스처/에셋 메모리 사용량 추정
- 오브젝트 풀 vs 인스턴시에이트/디스트로이 패턴
- 누수된 레퍼런스
- `TObjectPtr` 올바른 사용 여부 (UE5 표준)

**렌더링 대상 (해당하는 경우):**
- 드로우 콜 추정
- 투명 오브젝트 오버드로우
- 셰이더 복잡도
- 비최적화 나이아가라 시스템
- LOD 또는 오클루전 컬링 누락

---

## Phase 4: 프로파일링 리포트 생성

```markdown
## 성능 프로파일: [시스템 또는 전체]
생성일: [날짜]

### 성능 버짓
| 지표 | 버짓 | 현재 추정치 | 상태 |
|------|------|------------|------|
| 프레임 타임 | [16.67ms] | [추정] | [OK/경고/초과] |
| 메모리 | [목표] | [추정] | [OK/경고/초과] |
| 드로우 콜 | [목표] | [추정] | [OK/경고/초과] |

### 병목 지점 식별
| # | 위치 | 이슈 | 예상 영향 | 수정 난이도 |
|---|------|------|-----------|------------|

### 최적화 권장사항 (우선순위 순)
1. **[제목]** — [설명]
   - 위치: [파일:라인]
   - 예상 개선: [추정]
   - 리스크: [낮음/중간/높음]
   - 접근법: [구현 방법]

### 빠른 개선 (1시간 미만)
- [간단한 최적화 1]

### 조사 필요
- [실제 런타임 프로파일링으로 영향 확인이 필요한 영역]
```

리포트와 함께 요약 출력: 상위 3개 병목, 버짓 대비 여유 추정, 권장 다음 조치.

---

## Phase 5: 범위 및 타임라인 결정

중간 또는 높은 난이도의 수정 항목에 대해 사용자에게 선택 제시:
- **A) 최적화 구현** (지금 수정 또는 일정 예약)
- **B) 기능 범위 축소** (`/scope-check` 트레이드오프 분석)
- **C) 성능 저하 수용 후 나중에 처리** (알려진 이슈로 기록)

이 스킬은 읽기 전용 — 파일을 작성하지 않는다.

---

## 규칙
- 측정 없이 최적화하지 않는다 — 직감에 의존한 성능 판단 금지
- 권장사항에는 반드시 예상 영향 포함 — "더 빠르게"는 실행 가능한 지침이 아님
- 정적 분석(이 스킬)은 후보를 식별; 런타임 프로파일링이 확인
